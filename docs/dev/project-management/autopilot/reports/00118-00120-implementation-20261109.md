## Deviations from the PRD text (all deliberate)

- 00119: the PRR heading is `# <title>`, not `# PRR: <title>`. bim's
  `align_h1_to_title` fixer keeps the H1 equal to the title, so the prefix
  would not survive `bim format` either.
- 00119: hook warnings reach `--json` as an additive `warnings` key; without
  it a missing `path_projects` root was invisible to scripts.
- 00119: hooks run after the path reservation and before the save, so a hook
  failure fails the create (`hook failed: ...`) with nothing written, instead
  of 00118's "note saved, but hook failed" wording.
- 00120: `daily_log`, `linked_contacts` and `archive` are additive JSON keys;
  `path_daily` and `path_articles` are keyword-only constructor arguments that
  default to None (feature off) so the TUI and serve call sites and existing
  tests keep working. The CLI always passes them from settings.
- The argument-count lint (PLR0913/PLR0917) is ignored per file for
  `serve/_app.py` and `tui/create_note.py` in pyproject, the same precedent as
  `runlog.py`.

- Fixed: the `bim serve` `create_note` action now forwards `body`, `summary`,
  `dry_run`, `daily_log` and `link_contacts`; `source` stays CLI-only on purpose
  (a request-derived path with only the inbox check as confinement).
- Fixed: dead `except AttributeError` in `set_default_id` removed.
- Rejected: "CRLF frontmatter is not stripped": `Path.read_text` translates
  `\r\n` before the regex runs, and `test_source_frontmatter_is_stripped_and_file_trashed`
  writes a CRLF source; a closing `---` as the last line is a tested contract.
- Accepted, documented in AGENTS.md: `bim create --json` prints through
  `click.echo`; `console.print(mode="raw")` renders a Rich `Text` that wraps at
  80 columns when stdout is not a terminal, which would split the JSON line.
- Accepted: a project's resources folder is created by the pre-save hook, so a
  save failure leaves an empty folder behind; `mkdir(exist_ok=True)` makes the
  retry harmless.
- Fixed in a follow-up commit: the Rust `_core` default-id fixer
  (`src/rust/src/consistency/defaults.rs`) formats the date's own offset, its
  default date is local time, and both filename-date parsers
  (`zettel_file_parser.py`, `src/rust/src/parser/enrichment.rs`) read the
  digits as local time. The parity test `test_date_title_from_filename` no
  longer skips `date`/`id`, and
  `test_default_id_follows_the_dates_own_offset_in_both_paths` pins both paths
  to `20240913120000` for `2024-09-13T12:00:00+02:00`.
- Deferred: `article` cannot be created from the TUI, which has no body or
